# OpenCTI AI Bench v2

## بستهٔ طراحی و پیاده‌سازی مرجع — نسخهٔ ۲٫۰٫۰

این بسته توسعهٔ پیشنهادی بنچمارک توصیف‌شده در **AI-Benchmark-Report.pdf** است. همان سه مجموعهٔ **Assistive / Grounded / Agent** و همان پنج فاز حفظ شده‌اند؛ اما داده، قرارداد پاسخ، نمره‌دهی و ثبت اجرای نسخهٔ جدید مستقل و صریح هستند. **کد و snapshotهای بنچمارک قبلی در اختیار تهیه‌کننده نبودند؛ این بسته نسخهٔ اصلاح‌شدهٔ آن مخزن یا نتیجهٔ اجرای مدل شما نیست.** [U1، صفحات ۱، ۲ و ۸]

## شروع سریع — بدون OpenCTI و بدون مدل

Python 3.10 یا جدیدتر کافی است؛ هسته وابستگی ثالث ندارد. از داخل پوشهٔ بسته اجرا کنید:

```bash
python -m ctibench validate
python -m unittest discover -s tests -v
python -m ctibench list --suite C
```

آزمون اتصال واقعی subprocess به ابزارها، فقط برای کیس C01:

```bash
python -m ctibench run \
  --case C01 \
  --agent-command "python examples/transport_smoke_agent.py" \
  --out runs/smoke-c01 \
  --repeat 3
```

این برنامه یک حل‌کنندهٔ قطعیِ کوچک برای C01 است؛ **مدل زبانی و ایجنت عمومی نیست**. قبول‌شدن آن فقط نشان می‌دهد مسیر پیام، ابزار، شواهد، ثبت اجرا و داور برای این سناریو کار می‌کنند.

نمره‌دهی دوبارهٔ همان اجرا:

```bash
python -m ctibench grade \
  --run-dir runs/smoke-c01 \
  --audit-key runs/smoke-c01/.audit-key
```

برای هر آزمایش، پوشهٔ خروجی تازه انتخاب کنید. کلید audit را منتشر نکنید. در محیط ارزیابی مستقل، کلید را خارج از دسترسی برنامهٔ نامزد نگه دارید؛ کلید محلی پیش‌فرض فقط برای توسعه است.

## اتصال مدل محلی

`examples/local_chat_agent.py` یک نمونهٔ حداقلی برای سروری با مسیر `/v1/chat/completions` و پشتیبانی tool calling است؛ این نمونه در زمان ساخت بسته روی یک مدل واقعی اجرا نشده است. تنظیم parser ابزار و پشتیبانی مدل/سرور باید در محیط شما بررسی شود. مستندات vLLM نیز پیکربندی tool calling را وابسته به مدل و parser توصیف می‌کند. [R5]

```bash
export LOCAL_LLM_BASE_URL=http://127.0.0.1:8000/v1
export LOCAL_LLM_MODEL=YOUR_SERVED_MODEL_NAME

python -m ctibench run \
  --case C01 \
  --agent-command "python examples/local_chat_agent.py" \
  --pass-env LOCAL_LLM_BASE_URL \
  --pass-env LOCAL_LLM_MODEL \
  --metadata examples/experiment.template.json \
  --out runs/local-c01 \
  --repeat 3
```

نام مدل و اطلاعات نمونهٔ metadata را قبل از مقایسه واقعی پر کنید. در صورت نیاز به کلید محلی، از `LOCAL_LLM_API_KEY` و `--pass-env LOCAL_LLM_API_KEY` استفاده کنید؛ کلید را در آرگومان فرمان یا فایل دادهٔ کیس نگذارید. نمونه به‌صورت پیش‌فرض مقصد عمومی را نمی‌پذیرد؛ فعال‌کردن عمدی `LOCAL_LLM_ALLOW_REMOTE=1` اجازه ارسال داده به سرویس بیرونی می‌دهد و مسئولیت آن با اجراکننده است.

این baseline فقط یک نمونهٔ اتصال است؛ مهارت، حافظه و معماری اختصاصی شما را بازسازی نمی‌کند. برای ارزیابی آن معماری، همان قرارداد ورودی/خروجی را به runtime خودتان متصل کنید.

## اتصال ایجنت خودتان

فرمان ایجنت باید از stdin یک پیام `task` بخواند. ابزارها را با پیام‌های `tool_call` درخواست کند و در پایان یک پیام `final` مطابق `schemas/answer.schema.json` بنویسد. stdout فقط برای پروتکل است؛ logها روی stderr باشند. prompt و context عمومی ارسال می‌شوند، نه جواب‌های طلایی.

```bash
python -m ctibench run \
  --suite C \
  --agent-command "python /path/to/your/benchmark_adapter.py" \
  --out runs/your-agent-v1 \
  --repeat 3
```

جزئیات پروتکل، سازگاری MCP/GraphQL و محدودیت ایزوله‌سازی در `docs/INTEGRATION_FA.md` آمده است.

## تفسیر نتیجه

`PASS` یعنی تمام گیت‌های همان کیس و در صورت نیاز بازبینی معنایی آن پذیرفته شده‌اند؛ نه اینکه مدل در تمام کاربردها درست است. `NEEDS_REVIEW` یعنی چک‌های خودکار کافی بوده‌اند اما کیفیت متن آزاد هنوز بررسی نشده است. `NOT_RUN`، `SKIPPED`، `ENV_INVALID`، `RUN_ERROR` و `AUDIT_UNVERIFIED` وضعیت‌های مستقل‌اند؛ هیچ‌کدام امتیاز کامل یا صفرِ مصنوعی نمی‌گیرند.

برای پرسش‌های مجموعه‌ای، precision، recall، F1 و تطبیق دقیق جدا ثبت می‌شوند. نمرهٔ واحد وزنی که خطای امنیتی را پشت چند چک ساده پنهان کند نداریم. فراخوانی ابزار و زمان از gateway ثبت می‌شود؛ **توکن‌ها بدون ناظر مستقل `null / NOT_MEASURED` هستند، نه صفر**.

## چه چیزهایی هنوز اتصال محیطی می‌خواهند؟

**OpenCTI زنده:** در این بسته adapter نسخه‌خاص GraphQL یا mutationهای داخلی ساخته نشده است. هسته روی fixture آفلاین کار می‌کند. طراحی اتصال و مسیر مهاجرت ارائه شده، اما import یا اجرای واقعی روی پلتفرم شما انجام نشده است.

**ATT&CK و OTX واقعی:** `external/snapshot_manifest.template.json` و `external/identity_map.template.json` باید با فایل و شناسه‌های واقعی شما پر شوند. پاسخ‌های واقعی را پس از freeze و کنترل import بسازید؛ از تعدادهای نوشته‌شده در PDF به‌عنوان oracle اجرایی استفاده نکنید.

**STIX:** export موجود، یک گزینه برای شروع import در محیط آزمایشی است. JSON و پیوندهای داخلی آن کنترل شده‌اند؛ validator کامل STIX و OpenCTI در محیط ساخت بسته در دسترس نبودند. موفقیت import، نگاشت deprecated و اعمال ACL باید جداگانه تأیید شوند. فایل گراف JSON مرجع رسمی هستهٔ آفلاین است، نه نتیجهٔ import.

**امنیت و حافظهٔ چندکاربره:** نقش و فیلتر دید در gateway آفلاین آزموده می‌شوند؛ اما این موضوع اثبات امنیت سشن، cache، MCP transport یا ACL واقعی پلتفرم نیست. آزمون‌های end-to-end پیشنهادی در سند طراحی آمده‌اند.
